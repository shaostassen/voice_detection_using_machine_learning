SpeechLens

Local language identification and robust transcription. Point it at audio, get back the language with a calibrated-ish probability, a transcript with per-segment confidence, and an honest set of warnings — computed entirely on your own hardware, with no cloud calls.

Context

Whisper is easy to call and hard to trust. Left at library defaults it hallucinates fluent text over silence and music, loops on itself, and reports none of it — the output looks identical whether the model heard a sentence or a fan. For anything unattended, a confident wrong transcript is worse than no transcript.

The interesting engineering is therefore not the model. It is the harness around it: deciding what is speech before decoding, deciding what language it is without trusting a single window, and marking low-quality output instead of silently passing it along.

Approach

  • VAD gating first. Silero (ONNX, CPU) segments speech before the decoder ever runs — the single largest anti-hallucination measure, since the most reliable way to stop the model inventing words over noise is to not hand it the noise. An energy-VAD fallback keeps the path alive if the ONNX assets are unavailable.
  • Chunk-voted language ID. Rather than trusting one window, several chunks each vote, and the distributions fuse as a log-space geometric mean. The property that buys: two clean windows can veto one corrupted window, because a near-zero probability anywhere drags the fused score down multiplicatively rather than being averaged away. Each vote costs an encoder pass only — the lazy segment generator is deliberately never consumed.
  • An explicit decode contract. Every robustness knob lives in one RobustnessConfig dataclass instead of scattered call sites, so the decode behavior is inspectable, diffable, and testable rather than a pile of implicit library defaults.
  • Confidence that surfaces. Per-segment confidence is exp(avg_logprob) — the geometric mean token probability — and anything under the threshold is flagged in the output schema, the CLI, and the web UI. The design goal was that flags rise before the transcript goes bad. The noise sweep was built to falsify that, and did: see below.

Context carry-over is off by design. It is the setting that makes Whisper read fluently and the setting that lets one hallucinated segment condition the next into agreeing with it. Error propagation is the worse failure. These defaults are load-bearing: changing one requires an A/B on the SNR sweep, recorded in the validation log.

Result

  • 12.2×realtime · large-v3 · T4
  • 33%WER at −5 dB SNR
  • 5/5languages identified
  • 30tests · 0 weights

On a free-tier Tesla T4, large-v3 at float16 decodes at RTF 0.082 — 12.2× faster than realtime. The number that matters more for a tool built to run locally: no GPU is required at all. On a Ryzen 9 9950X, large-v3 at int8 still runs at 3.9× realtime and small at 15.9× — and on base the CPU actually beats the T4 (0.028 vs 0.038), because a 23-second clip never saturates the GPU. Under white noise the transcript degrades gracefully rather than falling off a cliff: 3% word error on clean audio, 33% at −5 dB SNR, with the language still correctly identified at every step of the ladder. Chunk voting held English at p=1.00 down to 5 dB and decayed smoothly from there instead of staying falsely pegged.

The test suite runs in seconds with no network and no model weights, on every push, across Python 3.11 and 3.12. That is a deliberate architectural property, not a convenience: the pipeline takes its transcriber and detector by injection, so the orchestration logic is testable without three gigabytes of parameters. Anything that genuinely needs weights lives in a separate validation harness and never in the test suite. Three interfaces sit on the one pipeline — a Python API, a CLI, and a FastAPI service with a single-page web UI — under a hard dependency ceiling: no torch.

What the measurements refuted

Two of the harness's design assumptions did not survive contact with the sweep, which is the point of running it. An inert safety net is worse than none — it implies a guarantee that is not there — so both of these mattered more than the throughput numbers.

  • The confidence gate was inert, and chasing why exposed something worse. Flagged-segment count was zero at every noise level, including −5 dB where one word in three is wrong. First diagnosis: the threshold, 0.55, sat below the lowest confidence the model ever produces, so it could never fire. Raising it to 0.85 made the flag work — and was still wrong. Reading faster-whisper's source showed why the confidence values had looked so strangely uniform: avg_logprob is computed once per 30-second decode window and copied onto every segment from that window. A 130-second clip yields 22 segments and exactly 5 distinct values. The number the gate flags on is a per-window judgement wearing a per-segment label, so inside a window it cannot rank anything at all.
  • The signal that works was already in the output, unread. Per-word token probabilities are computed by the decoder, serialized into the JSON, and consumed by nothing. Labelling every word correct or incorrect against a reference via Levenshtein backtrace, then measuring how well each score ranks errors within a single noise condition: per-word probability reaches AUROC 0.89 on clean audio, against 0.58 for the segment signal the gate uses — near chance, exactly where errors are rarest and a flag is most valuable.
  • The optional denoise stage made things worse. Spectral gating was expected to start paying off at low SNR. It never did: word error rose at every level, and the gap widened as conditions got worse, reaching +15 points at −5 dB. It stays off by default and is not recommended at any SNR tested.
  • A published result failed to replicate. Entropy-based confidence estimators are reported to detect errors 1.5–4× better than probability-based ones — for CTC and transducer models. On Whisper, five estimators landed within 0.008 AUROC of each other: no advantage at all. What did help was the aggregation rather than the estimator — taking the minimum over a word's tokens instead of the mean, worth 10–25% in error-detection precision, since a word is wrong if any one of its tokens is and averaging dilutes exactly that evidence.

Every number here carries the hardware, model, compute_type, and date that produced it, with raw logs committed alongside. All of the above is one 23-second LibriSpeech clip — enough to characterize behavior and cost, not a corpus benchmark, and labeled that way in the validation log. An unsourced number is a bug.
